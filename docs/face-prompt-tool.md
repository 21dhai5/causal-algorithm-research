# 人脸提示词工具

输入一句描述，得到一段可复制的人脸图像提示词。工具保留明确要求，补全未指定的外貌和画面细节；也可显式设计表情、强度及触发情境。同一句话可以重复生成，探索不同版本。**这里只生成文字，不生成图片，也不判断两张脸是否属于同一个人。**

这是与仓库因果效应研究分开的规则设计工具。返回模式为 `rule_based_design`，不是从训练数据学习的因果推断，也不是因果效应估计器。

## 在本机打开

使用 Python 3.12+，在仓库根目录运行，无需安装第三方依赖或提供 API 密钥：

```powershell
python -B experiments/run_face_prompt.py --serve
```

保持终端运行，在浏览器打开 <http://127.0.0.1:8765>。填写人物描述后，可选表情、强度与触发情境，再点击“生成完整提示词”；结果出现后可复制，或点击“再生成一版”。也可使用 `Ctrl + Enter`，macOS 使用 `⌘ + Enter`。

端口被占用时可改用：

```powershell
python -B experiments/run_face_prompt.py --serve --port 8766
```

此时打开 <http://127.0.0.1:8766>。服务仅监听本机回环地址；停止工具时在启动终端按 `Ctrl + C`。不要直接双击 `web.html`，页面需要同源的本机接口。

页面包含等待、失败重试和复制状态。若无法连接，请确认启动命令仍在运行；复制被浏览器限制时，工具会尝试兼容复制，仍失败则选中文本，提示手动按 `Ctrl / ⌘ + C`。补全说明可在结果下方展开查看。

## 相同输入，多种补全

例如连续使用：

> 一位30岁左右的女性，棕色短发、雀斑，正面半身肖像，柔和自然光，写实风格。

这些明确条件完整保留。此例包含有限词法无法解析的年龄和雀斑，采用 24 组有条件的制作侧重变化，例如突出轮廓衔接或局部层次，不擅自补充外貌。使用“一位成年女性的写实肖像”等规则可识别的描述时，可补全未指定的脸型、五官、表情、姿态、光线与背景，最多 648 种组合；明确指定的维度越多，可用组合越少。并非每个维度都会在每次生成时变化。

工具对不支持解析的明确外貌要求采取保守保留方式，不应把它理解为已经准确识别所有自由文本。例如复杂的修饰关系、否定、多对象描述或特殊风格要求可能无法理解；请检查最终提示词和补全说明，必要时把要求写得更直接。原文的保留不等于工具理解了任意语义。

## 显式表情规则链

可选表情代码为 `neutral`（中性）、`joy`（喜悦）、`sadness`（悲伤）、`anger`（愤怒）、`surprise`（惊讶）、`fear`（恐惧）、`disgust`（厌恶）。强度为 `low`、`medium`、`high`，默认 `medium`。触发情境可留空；填写时必须为不超过 500 字符的非空文本。

选定表情后，规则按“作者设定的触发情境 → 作者选择的表情与强度 → 眉、眼、颊、嘴的可见肌肉变化”编排。例如喜悦可建议面颊上提与嘴角上扬。情境只是作者设定，工具不根据故事自动识别情绪，也不诊断真人心理或声称存在已识别的因果效应。

表情设计只调整原有面部肌肉，不随机补充脸型、五官比例、年龄、族裔、肤色或发型；连续生成可变化制作侧重，保持所选表情和强度。明确提及某个部位时保留该部位的原文限制，例如“闭眼、闭嘴”不会再收到开眼、张嘴建议。存在否定、原有表情或全局限定时，规则保守保留原文，不猜测约束作用域；复杂约束下可能仅返回有条件的设计说明。身份保持是一条提示词约束，不是对图像生成结果的保证。

不选择表情时，原有有限补全行为保持一致，`expression_plan` 为 `null`。此时只允许缺省强度 `medium` 和空情境；其他强度或非空情境需要先选择表情。

## 命令行使用

直接输出提示词：

```powershell
python -B experiments/run_face_prompt.py --text "一位成年男性，黑色卷发，正面肖像，纯色背景"
```

查看提示词、补全说明、版本标识和模式字段：

```powershell
python -B experiments/run_face_prompt.py --text "一位成年男性，黑色卷发，正面肖像，纯色背景" --json
```

显式设计喜悦表情，并查看规则链：

```powershell
python -B experiments/run_face_prompt.py --text "一位成年女性的正面写实肖像" --expression joy --intensity high --cause "与久别的朋友重逢" --json
```

`--expression`、`--intensity`、`--cause` 用于单次命令行生成；启动 `--serve` 时在页面提交这些选项，不能把它们作为服务启动参数。

默认历史位置为 `~/.causal-face/history.sqlite3`，其中 `~` 是当前用户主目录。需要独立历史时可指定路径；使用相同历史才能延续去重：

```powershell
python -B experiments/run_face_prompt.py --text "一位成年男性的写实肖像" --history face-history.sqlite3
python -B experiments/run_face_prompt.py --serve --history face-history.sqlite3
```

历史在本机保存**实际完整输出的哈希**，用于避免同一历史中返回完全相同的提示词，不保存输入或完整提示词正文。重复运行或重启后，只要继续使用同一历史文件，仍可查询已有哈希。历史文件损坏或不可写时，请处理错误后重试，不应把未成功登记的结果视为已纳入去重。

## 范围与限制

- 全部补全来自有限规则和组合语法，没有 LLM，也不使用 API 密钥、图像数据或训练数据；本机页面不加载外部字体、脚本或其他网络资源。
- 明确要求优先，但规则无法理解任意中文或英文语义。保守保留无法解析的要求可能减少可变化的内容，并不保证所有复杂约束都已正确理解。
- 去重针对完整输出文本的哈希。语义近似的提示词仍可能出现；没有图片生成、图像相似度或人脸身份验证，因此不保证实际生成的图像不同，也不保证人脸身份不同。
- 规则组合有限，不能承诺无限新版本。组合耗尽时需要调整输入要求；删除历史、切换到空历史或历史丢失后，跨次唯一性保证随之失效。
- 不收集观测、拟合因果模型或估计干预效应，不能据此声称外貌、光线或构图之间存在已识别的因果关系。

## 本机接口

页面调用同源 `POST /api/generate`，请求 JSON：

```json
{"prompt": "一位成年女性的正面写实肖像"}
```

可选字段请求示例：

```json
{"prompt": "一位成年女性，闭眼、闭嘴的正面肖像", "expression": "surprise", "intensity": "low", "cause": "收到意外的好消息"}
```

请求必须包含 `prompt`，仅可附加 `expression`、`intensity`、`cause`；未知字段、重复字段、错误类型、非法枚举、过长或空白情境均返回 HTTP 400。`expression` 可为 `null`，与省略等价；`intensity` 省略为 `medium`，`cause` 省略为空字符串，两者不能为 `null`。缺少表情时，非缺省强度或非空情境也返回 400。所有参数在候选生成和去重登记前统一验证；CLI 在打开历史文件前验证参数。

成功结果包含 `prompt`（完整提示词）、`assumptions`（补全说明字符串列表）、`variation_id`（版本标识）、`mode`（固定为 `rule_based_design`）和 `expression_plan`。显式选择表情时，`expression_plan` 为包含 `expression`、`intensity`、`cause` 及 `rules`（字符串列表）的对象，规则也同时写入完整提示词和补全说明；未选择时为 `null`。规则中的原文约束优先于表情设计。组合耗尽返回 HTTP 409，其他失败结果以 `error` 字段返回中文说明。客户端只以纯文本展示返回内容，不将描述或结果作为 HTML 执行。
