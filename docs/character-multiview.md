# 人物多视图因果提示词生成器

从同一份全身人物设定生成多个相机方位的提示词。人物描述、服装和地标保持固定，相机方位决定地标朝向相机、背向相机或处于掠射边界。输出包含完整提示词、逐视图提示词、负向提示词、身份文本指纹和可检查的依赖关系。

实现采用 Python 3.12+ 标准库，无需模型、API 密钥、图像、NumPy 或前端构建。只生成文字；模式字段为 `RULE_BASED_CAUSAL_DESIGN`，不是从数据学习的因果推断，也不生成图片或重建三维人物。

## 本机页面

在仓库根目录运行：

```powershell
python -B experiments/run_character.py --serve
```

在浏览器打开 <http://127.0.0.1:8767>。填写全身描述和风格，逐项添加非对称特征并选择其身体表面，再选择四视图、八视图或至少一个自定义视角，点击“生成多视图提示词”。支持 `Ctrl / ⌘ + Enter`。

“完整提示词”可整套复制；“逐视角检查”分别显示可见、隐藏、掠射特征，每个视图都能独立复制。“因果设计规则”展示共享约束和依赖关系。负向提示词可单独复制，JSON 可下载到本机。编辑任何输入后，旧版会标记为待更新，复制和导出在重新生成前不可用；重置和载入示例会撤销未完成的请求。

网页保留自由原文，不自动将任意描述拆成地标。需要按方位控制的局部特征，应在“不对称特征”中明确添加，并核对其表面归属与原文一致。网页的描述和地标是可分别编辑的输入，修改描述不会自动删除已有地标。

服务固定监听 `127.0.0.1`，不自动打开浏览器。端口冲突时可使用 `--port 8768`，此时访问相应端口。启动终端按 `Ctrl+C` 停止。不要双击包内 `web.html`，页面需要同源接口。

## 相机干预与身份不变量

设计目标是把“改变视角”限制在相机变量内，避免重新生成一套外貌或把左右标记镜像翻转。

- 身份由原始人物描述和按稳定 ID 排序的地标清单构成。`character_id` 是其 SHA-256 的前 24 位十六进制文本指纹；相机选择、排列和风格不参与计算。它用于核对输入设定，不是图像人脸识别或视觉身份保证。
- 坐标始终以人物自身为准，方位角从正面 `0°` 朝人物自身右侧递增：右侧 `90°`、背面 `180°`、左侧 `270°`。正面图中，人物右侧在画面左边；背面图中，人物右侧在画面右边。
- 每个地标绑定到 `front`、`back`、`left`、`right` 或 `all`。前四种有固定向外法线，依据 `cos(相机方位角 − 表面方位角)` 分类：大于 `1e-9` 为朝向相机，小于 `-1e-9` 为背向相机，其余为掠射边界。`all` 表示全周共同特征，仍要遵守实际遮挡。
- 背向地标保留在身份记忆中，但提示词禁止透过身体绘制或移到可见表面。掠射地标只能在真实轮廓允许时局部露出，不能推定完整可见。
- 每条单视图提示词只依赖固定身份、风格和自身方位；单独请求、加入批量或调整批量顺序，不改变这条提示词。默认要求同一站姿、尺度、水平相机和均匀光照，只改变相机方位。

支持的八个视图 ID 按方位顺序为 `front`、`front_right`、`right`、`back_right`、`back`、`back_left`、`left`、`front_left`。四个斜侧视图分别位于 `45°`、`135°`、`225°`、`315°`；默认四视图顺序为 `front,right,back,left`。

可见性只使用主表面朝向近似，没有真实三维体积、骨骼、遮挡网格、材质或深度求解。自由文本中的否定、多人物和特殊姿态不做通用语义解析；与统一站姿或地标冲突的描述须由作者修正。规则无法保证外部图像模型执行约束或维持同一视觉人物。

## 命令行与 Python 接口

省略人物描述时输出完整示例。自定义描述且省略 `--features` 时，地标清单为空，不注入示例旅行者的徽章、刺绣或配饰：

```powershell
python -B experiments/run_character.py --text "一位穿白色宇航服的成年宇航员" --views front,right,back,left
python -B experiments/run_character.py --views front,front_right,right,back --json
python -B experiments/run_character.py --json --output character.json
```

`--style` 指定共享风格，`--json` 输出完整结构化报告；默认输出提示词正文。`--output` 只创建新文件，拒绝覆盖已有文件。`--serve` 不能与生成或输出参数混用。安装项目后也可使用 `causal-character`，源码模块入口为 `python -B -m causal_character`（需设置 `PYTHONPATH=src`）。

`--features landmarks.json` 读取用户明确提供的 UTF-8 JSON 数组，例如：

```json
[
  {"id": "left_emblem", "label": "人物自身左臂外侧的橙色任务徽章", "surface": "left"},
  {"id": "back_unit", "label": "背部的矩形生命维持背包", "surface": "back"}
]
```

地标不依赖固定名称白名单。每项必须且只能包含 `id`、`label`、`surface`；`id` 在同一人物内唯一，为 1 至 64 个 ASCII 字母、数字、下划线或连字符；`label` 是 1 至 300 字符的非空文本。最多 40 项，允许空数组。描述最多 6000 字符，风格最多 1000 字符，视图为 1 至 8 个不重复的受支持 ID。输入超限或类型错误时明确拒绝，不截断。

Python API：

```python
from causal_character import generate_multiview_prompt

# 自定义描述不会补入默认人物的地标；显式地标由作者负责与原文保持一致。
result = generate_multiview_prompt(
    "一位穿白色宇航服的成年宇航员",
    style="写实全身角色设定图，浅灰背景，柔和均匀光照",
    views=["front", "right", "back", "left"],
    features=[{"id": "left_emblem", "label": "人物自身左臂外侧的橙色任务徽章", "surface": "left"}],
)
print(result["full_prompt"])
```

Python 接口的 `views=None` 使用默认四视图；`features=None` 只在描述与内置示例逐字相同时配套示例地标，否则使用空清单。显式 `features=[]` 始终保持为空。函数不修改调用方的列表或字典；输入错误抛出 `CharacterPromptError`（`ValueError` 子类）。同一输入可重复得到相同结果，没有随机补全或历史去重。

## 本机 JSON 接口

`GET /api/defaults` 返回共享示例与支持的视图、表面选项；`GET /api/health` 返回状态与模式。`POST /api/generate` 接受 UTF-8 `application/json`，只支持 `description`、`style`、`views`、`features`：

```json
{"description":"一位穿白色宇航服的成年宇航员","views":["front","back"],"features":[]}
```

字段可以省略；空对象使用完整示例。显式空白描述、空风格、空视图、未知字段、重复地标 ID、重复 JSON 键、非有限数字和显式 `null` 都会被拒绝，空地标数组有效。请求体和地标文件均最多 256 KiB。

成功报告包含 `schema_version: "character-multiview-v1"`、`mode`、`character_id`、`identity`、`style`、`views`、`causal_graph`、`consistency_rules`、`warnings`、`full_prompt`、`negative_prompt`。每个视图包含其 ID、中文名称、方位角、三类地标、独立提示词与负向提示词。失败返回中文 `error`，不回显作者原文或本机路径。

服务核对当前回环端口的 Host、同源 Origin 和 Fetch-Site，拒绝重复或不完整长度、分块传输和内容编码。页面仅使用随包脚本、样式与系统字体；用户内容通过文本节点或文本框显示。输入仅在进程和页面内存中处理，不写历史、访问日志或浏览器本地存储；只有显式导出或 `--output` 才保存结果。
