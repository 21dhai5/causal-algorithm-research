# 逐元素特效提示词

本工具只生成特效提示词与对应的文字数据。元素数量、名称、细分层级及属性由输入决定，不预设角色、招式、剑气、护盾等固定清单。

原有因果研究负责观测与统计估计，本工具使用显式引用、条件和依赖表达描述中的关系，不把先后排列当作因果，也不执行动画、伤害或物理求解。

## 使用

在仓库根目录运行 `python -B experiments/run_combat.py --serve`，打开 <http://127.0.0.1:8766>。

1. 输入完整创意，或载入可清空的详细示例。示例中的每个条目都是具体创作数据，不是通用元素模板。
2. 可逐行写 `名称｜属性=值｜属性=值`，或 `名称：完整细节`，再点击“从分项文字读取”。
3. 在逐项编辑器增删元素，指定父元素，自由添加属性；同名元素用不同 ID 区分。例如刃缘反光、刃口缺口、不同位置的漂尘分别记录，不合成一句“武器与环境”。
4. 在“交互定义”中选择具体作用两端，写出触发条件、可见响应与前中后状态；依赖关系只按明确填写的 ID 保存。
5. 生成完整提示词，检查各元素的独立提示词，复制文字或导出 JSON。

修改原文会关闭逐项清单的提交，并使旧结果失效；核对清单后可重新启用，避免把上一个场景的元素混入新场景。改名会同步引用；存在子项或交互引用的元素不可直接删除。

普通叙述无法由有限规则可靠拆解时，原文和字符跨度会完整保留，页面明确标记“待细化”。本工具没有接入语言模型，不声称从任意自然语言自动穷尽画面细节，也不会把未知内容填成已知事实。明确写出的数据会全部进入提示词，不按前若干项截断。

## 具体细节与对应数据

例如下列三行产生三个独立数据条目，而不是一个“剑气”大类：

```text
剑气内芯｜颜色=冷白｜截面=细窄菱形｜明暗=中心较亮且保留边界
内芯左侧薄焰｜颜色=半透明淡青｜位置=贴近内芯左缘｜运动=向后弯曲，未触及前景衣袖
尾迹末端散点｜数量=仅一粒｜位置=尾迹最远端｜状态=逐渐变暗，尚未消失
```

其他任意细节也可独立成项：接触亮斑的边缘、不同方向的裂纹、碎片的断面、雾层的透光缺隙、湿地中的局部反射。名称和属性没有词汇白名单。缺失或相互矛盾的属性需要作者明确，不会由固定战斗规则裁决。

Python 入口：

```python
from causal_combat import generate_prompt

# 每项均是明确的作者数据；自定义属性不需要属于预设分类。
report = generate_prompt(
    '两处局部细节的接触尚未确认。',
    elements=[
        {'id': 'core', 'name': '剑气内芯', 'attributes': {'颜色': '冷白', '位置': '画面左中'}},
        {'id': 'edge', 'name': '金色薄片左缘', 'attributes': {'状态': '尚未破裂', '折射层': '向内偏移的淡金细边'}},
    ],
    interactions=[{
        'source_id': 'core', 'target_id': 'edge',
        'trigger': '仅当内芯接触薄片左缘时',
        'response': '从实际接触处向上沿弧线出现细亮纹；尚未确认接触时不出现',
        'before': '两者之间仍有间隙',
        'during': '亮纹限于接触局部，不照亮整个画面',
        'after': '不额外添加碎裂结果',
    }],
)
print(report['full_prompt'])
```

元素字段为 `id`（可省略并自动编号）、`name`、可选 `parent_id` 与 `attributes`。属性值支持字符串、有限数值、布尔值和 `null`。父级必须存在且无环；同名不同 ID 不会合并。

交互字段为可选 `id`、`source_id`、`target_id`、`trigger`、`response`、可选 `before`、`during`、`after` 和 `depends_on`。条件、否定、未知状态逐字保留；依赖必须引用已列交互且无环。交互只描述“满足什么条件时应如何写”，不认定结果已经发生。

## 命令行与接口

```powershell
python -B experiments/run_combat.py --text "刃口缺口｜形状=小月牙｜位置=刃尖下方"
python -B experiments/run_combat.py --text "刃口缺口：边沿较暗，尚未扩大" --json --output prompt.json
python -B experiments/run_combat.py --inventory my-elements.json --output prompt.txt
```

默认输出提示词正文，`--json` 输出报告。`--inventory` 读取作者指定的本地 JSON 文件，内容为 `{"elements": [...], "interactions": [...]}`；未同时指定 `--text` 时使用空上下文，避免混入示例。输出文件独占创建，存在时拒绝覆盖。

`GET /api/defaults` 返回示例原文、元素清单与交互。`POST /api/generate` 必须提供 `text`，可提供 `elements`、`interactions`；显式空数组表示空清单。只有原文时读取明确的分项语法，缺省不载入示例元素或交互。

响应为 `schema_version: "vfx-prompt-v2"`、`mode: "PROMPT_ONLY"`，包含原文、元素和交互的独立 `prompt`、来源、`unresolved_fragments`、`warnings`、`full_prompt` 与 `negative_prompt`。用户清单标记 `explicit_inventory`；逐行语法带 `explicit_text` 引文。界面呈现普通文字，输入不会作为 HTML 执行。

资源限制：原文最多 20000 字符，最多 400 个元素、每项 80 个属性、600 条交互，单字段最多 4000 字符，总输入 JSON 最多 200000 字符；HTTP/清单文件最多 256 KiB。超限明确报错，不静默删减。数量限制用于约束本地请求资源，不规定画面应当有哪些元素。

旧版 `build_combat`、蓄力/伤害参数、帧、战果、播放器和二维绘制已移除；命令与本机端口保留作为提示词工具入口。

## 本版验证

2026-11-13 已检查不同数量的独立条目、同名不合并、全部属性保留、父子及交互引用、条件与否定原文、普通叙述的未确认跨度。桌面及 390 像素手机页面实测覆盖编辑、分项读取、复制、导出、旧结果失效、迟到请求隔离和 HTML 转义，页面不含绘制画布或战斗参数。

原有合成研究、足球分镜、人脸提示词入口回归通过；回环来源、重复 JSON 字段、旧参数、非有限数值及请求上限检查通过。验证只说明文字编排和输入数据的保留行为，不证明通用语义抽取能力。
