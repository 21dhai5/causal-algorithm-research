# 一剑因果：玄幻战斗素材与互动预演

这是一条从中文创意到元素描述、交互事件和可播放帧的素材设计流程。页面使用原生 Canvas 2D 绘制剑修、剑气、护盾和接触反馈；后端负责计算事件与结果，前端读取同一份数据播放。

当前输出是**生成的文本描述、素材提示词和结构化场景数据**。画面是程序化二维预览，不是已经生成的图片、视频或三维资产。当前规则属于显式的创作设计模拟，不是从实验观测数据中识别或学习出的因果效应。

## 启动与使用

在仓库根目录运行：

```powershell
python -B experiments/run_combat.py --serve
```

服务默认地址为 `http://127.0.0.1:8766`。打开该地址后，页面自动生成第一份素材，停在开场，等待手动播放。

1. 输入创意描述，例如「青衣剑修向玄金护盾斩出青色剑气，破盾后的余能决定目标受击与地面碎裂」。
2. 调整蓄力、距离、护盾、瞄准偏移和整数种子。参数变动会暂停旧战斗并重新生成；相同参数和种子可重复检查。
3. 点击「播放」，观察剑气飞行、护盾形变、接触火花和条件满足后出现的余波与碎片。摄像机震动只发生在有效的接触反馈帧，系统选择减少动态时关闭震动并减少粒子。
4. 使用「暂停」「重播」「回到开场」或拖动时间轴。点击因果事件可跳到其开始时刻；当前生命、灵力、护盾和地面读数都取自当前帧。
5. 在「素材档案」选择具体元素，检查稳定 ID、位置等数据、描述、材质提示词和来源依据。「整段分镜」提供完整描述与提示词。
6. 复制当前面板的提示词或下载完整 JSON。剪贴板权限不可用时，页面选中原文供手动复制。JSON 下载在浏览器本地完成。

四组预设用于对照破盾命中、全部格挡、瞄准偏离和灵力不足。预设仅设置输入，结果始终由服务端规则决定。页面的「全片推演结果」显示已生成的完整摘要；舞台下方的「当前」读数显示播放时刻的实际帧状态，两者用途不同。

## 元素注册表

每个角色、护盾、地面或特效素材都有独立 `id`。`attacker`、`defender`、`shield`、`ground` 是前端使用的基础标识；其他特效通过帧中的 `element_id` 与注册表关联。

一个元素包含：

- `id`、`kind`、`label`：稳定标识、类别和可读名称。
- `owner_id`：角色所有权，场景元素可以为 `null`。
- `data`：可用于引擎搭建的参数，其中 `position_m` 是米制 `[x,y,z]` 世界坐标。
- `description`：人物、造型、动作或材质的中文说明。
- `material_prompt`、`negative_prompt`：后续素材制作的正向与排除提示词。
- `source.basis`、`source.quote`：该描述或设计参数的来源依据与引用。

世界中进攻者位于 `[0,0,0]`，防守者位于 `[distance_m,0,0]`，剑气通常在 `y≈1.2 m` 的躯干高度飞行，`z` 表示瞄准偏移。前端以透视错位表现 `z`，二维投影本身不承担碰撞判断。

## 交互链与单位

交互按「输入与初态 → 蓄力与发射前置条件 → 距离传播 → 几何接触 → 护盾吸收 → 余能与伤害 → 条件反馈」展开。事件通过 `depends_on`、`preconditions`、`updates` 与 `causal_relations` 解释依赖。未发射或未接触时，不应出现接触扣血、受击震动或凭空碎盾。

- `charge`：无量纲蓄力比例，页面范围 `0–1`，步长 `0.05`。
- `distance_m`：米，页面范围 `2–24`，步长 `0.5`。
- `shield`：护盾设计强度，页面范围 `0–120`，步长 `1`。
- `aim_offset_m`：米，页面范围 `−5–5`，步长 `0.1`。
- `seed`：非负整数；页面范围 `0–2147483647`。
- 事件与帧的时间：秒。帧是 `30 Hz` 固定步长，并包含精确结束帧。
- 能量、护盾强度与生命伤害：设计单位，不宣称为焦耳、帕斯卡或实测人体伤害。

具体蓄力函数、距离衰减、发射阈值、碰撞半径、伤害与地面破坏阈值以当前后端规则、响应 `assumptions`、事件 `evidence` 和 `interaction_rules` 为准。前端不复制这些公式，避免规则升级后出现两套结果。

本版采用以下设计规则：蓄力小于 `0.15` 不发射；发射灵力为 `100 × charge`。剑气从剑尖 `[0.65,1.2,0]` 出发，沿实际路径每米衰减 `0.8` 单位。有盾先在身体前方 `0.6 m` 检测，无盾在身体位置检测；达到检测面且尚有灵力、横向偏移绝对值不超过 `0.75 m` 才接触。护盾吸收 `min(盾强, 接触灵力)`，命中伤害为 `min(100, 穿盾余能 × 0.8)`。命中且穿盾余能至少 `20` 单位才触发贴地冲击波与后续石屑。这些数值是可修改的创作规则。

能量传递的读数顺序为 `attack_energy → energy_at_contact → absorbed_energy → remaining_energy`。有效接触时，护盾吸收受接触能量与当前护盾容量约束，余能由吸收后的剩余量决定；是否造成伤害、是否出现冲击波和地面裂纹继续依照后端事件条件。失去几何接触时，不能仅凭高能量认定命中。

## 同源接口

`GET /api/defaults` 返回页面初始输入：

```json
{
  "text": "青衣剑修向玄金护盾斩出青色剑气。",
  "charge": 0.8,
  "distance_m": 8,
  "shield": 50,
  "aim_offset_m": 0,
  "seed": 7
}
```

`POST /api/generate` 接受相同结构。PowerShell 调用示例：

```powershell
# 用 UTF-8 传递中文创意，结果保留完整元素与播放帧。
$combatBody = @{
    text = '青衣剑修凝聚剑气，击中玄金护盾后按余能产生碎片与冲击。' # 创意原文。
    charge = 0.95 # 无量纲蓄力比例。
    distance_m = 6 # 交战距离，米。
    shield = 24 # 初始护盾设计强度。
    aim_offset_m = 0 # 瞄准偏移，米。
    seed = 7 # 可重复的整数种子。
} | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:8766/api/generate' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($combatBody))
```

响应契约为 `schema_version: "fantasy-combat-v1"`，`mode: "RULE_BASED_DESIGN_SIMULATION"`。完整 JSON 包含：

- `input_text`、`parameters`、`duration_s`、`assumptions`：原始输入和设计边界。
- `elements`：可追溯元素注册表。
- `events`：带起止时间、参与元素、触发条件、状态更新、前中后关键帧和依据的事件。
- `causal_relations`、`interaction_rules`：显式关系与可读交互规则。
- `initial_state`、`final_state`：扁平状态，如 `attacker.energy`、`defender.hp`、`shield.strength`、`ground.cracked`。
- `frames`：`t_s`、`phase`、`projectile_position_m`、`state`、`active_event_ids`、`effects`。效果种类包括 `charge`、`trail`、`impact`、`shield`、`debris`、`shockwave`、`afterimage`；每个效果给出 `element_id`、`strength`、`position_m` 和 `progress`。其中 `strength` 控制明暗，冲击波与碎石的 `progress` 单调控制传播位置；冲击波位于离地 `0.03 m` 的贴地平面。
- `outcome`：`hit`、`blocked`、`miss` 或 `insufficient_energy`，以及能量、吸收、余能、伤害、剩余护盾与接触时刻等结果。
- `description`、`full_prompt`、`negative_prompt`：整段分镜的文本素材。

播放器每帧只选择不晚于当前时间的服务端帧。它不会在浏览器中重新计算战果，也不会使用最终状态提前画出破盾、扣血或地裂。输入变化会立即取消旧请求与播放，并以请求版本隔离迟到响应。页面不强制自动播放，不使用外部字体、素材、脚本或生成 API。

## 从描述到引擎素材

导出的数据可作为后续制作的交接资料，仍需由创作者或独立管线完成资产制作与引擎接入：

- **Unity VFX Graph**：用元素 ID 对齐角色与效果，用材质描述指导 Shader/VFX Graph 的颜色、发光、粒子形状，用事件时间与 `strength` 驱动触发与强度曲线。
- **Unreal Niagara**：将素材描述整理为系统与发射器设计，以事件参与者和接触位置设置 Niagara 参数；将护盾状态更新映射到材质与破碎表现。
- **Blender**：据角色、剑气和护盾描述建模与制作材质，用世界位置和事件关键时刻安排动画，再由独立渲染流程输出镜头。

当前页面没有集成这些引擎，也不自动生成其工程文件。导出的米制坐标、稳定标识和完整事件链使后续实现有明确依据；风格提示词用于美术沟通，不能替代真实资产或引擎特效网络。

## 实际验证

2026-11-13 使用 Python 3.12.10、Node.js 24 和无窗口 Edge 执行：

- 四种主分支，以及无盾、途中耗尽、`0.75 m` 接触边界两侧的回放；检查确定性、有限数值、事件先后、帧状态字段一致性与精确终态。
- 桌面 `1440 × 1000` 和手机 `390 × 844` 页面；检查播放、暂停、拖动至精确末帧、回到开场、素材切换、整段提示词与 JSON 下载。
- 连续调参的迟到请求隔离、创意文本的 HTML 转义、减少动态效果设置；浏览器无脚本错误，手机页面无横向溢出。
- 独立审查后，将冲击波、碎石的传播进度与亮度分离；实测绘制半径单调向外增加。手机布局按预览、参数、事件与素材排列，参数区不再位于全部详情之后。
- 原有合成研究 CI 配置、足球分镜连续性及离线图片状态、人脸提示词入口；均执行成功。
- 在临时副本构建 wheel，确认包含战斗页面及 `causal-combat` 入口；确认已有 JSON 输出不会被覆盖。验证临时文件已清理。

CI 增加四种主分支与接触前状态约束检查。上述验证仅说明当前规则与程序化预览的一致性，不验证外部生成模型、三维引擎或现实物理。
