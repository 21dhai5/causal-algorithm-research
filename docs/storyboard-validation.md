# 分镜 MVP 实际验证记录

日期：2026-11-12。本记录对应当前分镜实现，不替代原有合成因果研究报告。

## 实际运行范围

- 使用 Python 3.12.10。新模块只依赖标准库；已用 `python -B -S experiments/run_storyboard.py` 在不加载 site-packages 的模式下运行猫坐窗边示例。
- 指定足球示例已运行，正式产物为 `examples/storyboard-football/storyboard.json`，包括整体场景、四个事件、两类关系、时间轴和三条完整图像提示词。
- 本次 `STORYBOARD_IMAGE_URL`、`STORYBOARD_IMAGE_MODEL`、`STORYBOARD_IMAGE_KEY` 均未配置，没有调用真实或付费图像服务。正式示例没有 PNG，图片状态为 `not_requested`、路径为 null。

## 核心与接口复核

根集成实际执行：

- 6 种时长（包括高精度 Decimal）× 6 种镜头数，共36种配置：镜头数准确、长度为正、首尾正确、时间与状态相邻连续、最终杯子完成倾倒。
- 5种空／否定／嵌套角色／额外情节／高桌冲突输入拒绝；8种无效参数拒绝。
- 后文补充的红色足球进入全部提示词；独立先后关系不产生因果边；完整同时分句共享故事区间。
- “男孩跑起来”之前不会提前处于 running；循环依赖明确拒绝。
- 离线 CLI、已有输出目录拒绝、缺图像配置拒绝、无虚假图片路径、UTF-8 中文标准输出通过。
- 原有合成研究入口用400样本、3个种子重跑，17项内置负对照通过；未改变原有研究算法。

两次独立审查分别检查事件引擎和图像／CLI。发现并修复：

1. 衣着宽匹配可能吞入额外人物和动词，改为有限衣着词法。
2. 后文颜色可能丢失，改为合并同一球的明确外观证据。
3. “跑起来”初态过早设为跑步，改为准备—开始—跑动状态转移。
4. 高精度 Decimal 首尾分叉，改为直接固定首尾端点。
5. 损坏 PNG 辅助元数据可能导致解码失败，现保存时只保留验证后的必要像素块与合法透明度，移除辅助元数据。

另在集成中修复 Windows 管道中文 JSON 的编码问题，标准输出明确为 UTF-8；倾倒结束后不再强行断言杯子继续接触球；空间使能关系与“导致”单独标注。

## 图像通路验证

使用临时本机 HTTP 服务和测试专用1×1 PNG，实际执行三个分镜 POST：两个返回可校验像素并保存，一个返回损坏 PNG。结果为 `generated / failed / generated`，失败路径为 null，CLI 返回3；剩余 JSON 和成功文件可读取。

另验证重定向拒绝、HTTP429不重试且错误正文脱敏；自定义供应方异常中的合成秘密不进入报告。检查4类损坏辅助元数据规范化和无效透明度拒绝。所有临时 HTTP 服务、像素文件、验证目录均已清理，不交付为模型图像。

## 提交前安全审查边界

端点通过环境变量配置，密钥只进入授权头，不写入报告；远程仅 HTTPS，本机允许回环 HTTP；不下载供应方 URL；禁止重定向并限制响应、PNG压缩／解压尺寸、块数和像素维度。图片仅用受限镜号命名并独占保存。未配置或未显式请求时不调用服务。

输出目录逐级检查链接并独占创建；不提供抵抗不可信共享目录恶意并发替换的句柄级隔离。socket 超时不是整个请求的总时长保证。提示词会发送给所选服务，调用前需确保数据适合该服务。审查不等于证明没有漏洞。

原型未测真实供应方兼容性、图像语义正确性、角色外观一致性或物理动力学；没有生成连续视频、音轨或进行统计因果识别。本轮官方图像文档请求受限，HTTP协议按项目明确约定实现，没有虚构文档核验成功。

可复现命令和简短断言见 [MVP说明](storyboard-mvp.md)；全部源码见 [源码汇编](storyboard-source.md)。

## 2026-11-13：环境器物优先与全场状态传播

本次独立提案与实现把有限环境解析、器物关系和单人物行为接入原有时间轴；交付标准是可复现的全元素状态、可追溯变化、错误前置拒绝和旧例兼容。执行环境仍为 Python 3.12.10；没有部署服务器、调用真实图像服务或生成连续视频。

### 根集成实际执行

- 5种输入 × 3种时长（含高精度 Decimal）× 4种镜头数，共60种配置：正长度、首尾覆盖、相邻时间和状态连续、离线图片路径为空、JSON可编码。输入包含两份新场景、最少环境开门、旧足球和旧独立并行。
- 最新40项拒绝／篡改检查通过，覆盖关门入室、上锁、重复动作、多人、冲突代词、重复器物引入、参照系不兼容、未来搬运条件倒灌、未知事件和顺序、条件作用域、未知运动、缺稳定支撑、非法参数、过大整数及修改派生输出。
- 正向复核深层未知位置保留、改变位置父体后局部方位归为未指定、条件化搬运支撑后代、拿走载荷后的规则读取依赖、DAG数组倒序、重复编译一致和墙画等无关元素保持。
- 两份正式JSON从当前源码重新生成并逐字段重建一致；`python -B -S` 的CLI输出与正式示例一致。默认均为6秒3镜头，没有PNG文件或假图片路径。
- 实际提取并执行提交中的两段CI内联脚本；原有合成研究以400样本、3个种子、100次块重抽样运行成功，17项内置负对照均为true。
- Python AST、JSON、TOML、YAML、说明链接、13个文件的完整源码快照逐字核对和 `git diff --check` 通过。验证只在内存或自动清理临时目录中运行，没有新增保留测试脚手架。

### 独立审查与修复

首次独立审查和后续复核发现并修复：未知父位置被过滤；可达判断误读说明文字；入室漏检入口所属区域；缺少稳定支撑／静止前置；普通拿取绕过载荷保持；未知动作和排序被执行；过大整数；未来平稳条件授权此前动作；更换位置父体沿用旧局部方位；房间方位被解释成桌面局部方位；重复器物身份合并和泛指人物代词冲突。

修复后最后一轮独立验证完成23个聚焦用例（15个预期拒绝、8个接受），并对两份正式基线重新编译，未发现阻塞。搬运与可达条件绑定事件、主体、目标和适用区域；说明文字不会成为执行开关。`state_dependencies` 同时保留读到的位置拓扑，是保守的规则执行依赖，不承诺最小原因集合。

独立发布安全复核覆盖本次11个源码、配置、说明与示例文件：凭据／私钥、私人绝对路径、联系方式、旧项目和其他并行任务内容的特征匹配均为0；未发现新增动态执行、文件或网络操作。新模块只导入标准库；CI仍只读、无secrets引用，checkout不保存凭据。该复核不构成不存在漏洞的保证。

### 本版边界

文本入口仍是有限单场景、单人物、每类器物一个身份的语法；不支持通用图像理解、复杂并行或物理动力学。结构化输入的证据标签及引文存在检查不认证来源或语义真实性，须使用可信解析器。结构化接口有节点／深度／整数限制，尚无总字节预算，不应直接暴露给不可信的大请求。静态图像适配器此次未改变，也未进行真实供应方、图像一致性或视频验证。
